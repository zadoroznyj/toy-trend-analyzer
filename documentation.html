Toy Trend Analyzer

Technical Documentation

Implementation reviewed: 24 November 2026. This page distinguishes implemented safeguards from approval-dependent plans.

Not an approval notice. YouTube/Google have not approved or endorsed the project. The local gate is disabled. No analysis requiring written Section III.L approval is active on real YouTube data.

Purpose and access

The Tool is a private toy-market research application with YouTube Data API collection, local SQLite storage, local report generation and an allowlisted Telegram bot. It is not a public analytics service. The application uses an API key and does not implement Google OAuth.

Architecture

Open the architecture diagram. The current data path is YouTube Data API → Python collectors → SQLite → local Markdown/PDF/HTML reports / authorized Telegram retrieval. A daily local retention service and timer are installed, enabled and active.

YouTube API methods

  • search.list — discovery of candidate videos/channels. The local Search.list cap is 50 calls per Pacific Time day across discovery modes; the quota reservation is shared and atomic. This is a local cap, not a Google grant.
  • playlistItems.list — enumerate uploads from known channel playlists.
  • videos.list — retrieve video metadata and public statistics in batches.
  • channels.list — retrieve channel metadata/statistics where requested.

The inspected video discovery rotates relevance, viewCount and date, date windows of 3/7/14/30 days, weighted regions and configured languages. Weights are experimental request allocation only. Region and language do not establish the creator, viewer or buyer location. The blind search experiment on 24 November 2026 saved raw results and did not calculate trend scores.

Currently implemented

  • SQLite stores video/channel metadata, timestamped statistic snapshots, search attribution, quota and collection state.
  • The current product evidence registry contains 24 manually curated product entries with manually linked source video IDs. The PDF and HTML catalogue list per-video source titles, channels, dates, observed views/likes/comments and statistics retrieval time. They are not automatic rankings and do not guarantee that every review in the corpus has been found.
  • Repeated publication context can be manually noted. Distinct channels are not assumed to be independent owners. No real-data author, channel, new-author-velocity or view-dynamics totals are calculated while the gate is off.
  • The proposed real-data metric code is guarded by config/compliance.json. The guard requires the owner-entered approved status/reference but cannot verify the Google decision. Synthetic fixtures test author identity deduplication, discovery-time author arrivals, comparable view snapshots and the provisional score. The algorithms remain approval-dependent.
  • Proposed score weights for future review: 40% verified independent authors, 25% new verified authors, 15% view dynamics, 10% freshness, 5% engagement and 5% market context. Missing inputs must remain unknown. A channel ID is not proof of a distinct owner.
  • The report generator embeds only a local image that has an exact product match and an explicit permission/license in reports/approved_product_images/sources.json. No real thumbnail is downloaded. At this review, the product PDF contains zero embedded product photographs because rights to copy the found images were not established.
  • The A4 PDF and responsive HTML catalogue use Unicode and clickable product/source links. The HTML is generated at reports/resale_toy_report.html. No photo is fabricated.
  • The bot’s /report sends the prepared PDF file. Generation uses a background worker and atomic replacement; it does not send messages during report generation tests.

Retention and deletion

The enabled daily systemd timer runs the cleanup service. The cleaner deletes API rows older than 30 days, expires matching source IDs in the manual product registry, clears recognized report caches, and invalidates Markdown, PDF and HTML catalogue outputs when source data expire. It expires recognized report copies in the project’s backups/ after 30 days, rewrites matching SQLite backup copies, and removes raw Discovery exports on their manifest deadline. Source-code backups are retained. With the gate off, derived tables and trend outputs are cleared; after approval they are limited to 36 months. The latest reported run succeeded, preserved 613 videos and 613 snapshots, and processed four SQLite backups without cleanup errors.

Coverage is limited to named project paths and recognized file patterns. The cleaner does not find or delete off-device/manual backup copies, files previously downloaded or shared, external/cloud service copies, or host system journal records. A local deletion-request workflow requires operator confirmation and does not delete data from YouTube or Telegram; contact the operator by email to submit a request.

Approval-dependent / not claimed

  • Written YouTube permission for III.L cross-video/cross-channel product analytics has not been obtained.
  • Real-data product classification, verified independent-author count, author-arrival velocity, view dynamics, trend score, and reports/distribution based on those metrics are not active.
  • No current trend, buyer geography, sales, retail prices, margin, product stock or market demand is claimed.
  • Permission to embed commercial product images has not been established; no approved real product photos are currently embedded.
  • The local retention timer is enabled, but external copies, prior downloads/shares and host journal records are outside its scope.
