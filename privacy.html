Who operates the tool

Toy Trend Analyzer is a closed, owner-operated research tool. It is not a public service and does not charge users. Only the Telegram chat configured by the owner is authorized to use the bot.

Information obtained from YouTube

When enabled, the tool uses YouTube Data API Services with an API key and without Google OAuth user authorization. Depending on the operation, it can receive public video and channel metadata, including video and channel IDs, titles, descriptions, tags when returned, publication time, duration, thumbnail URL, channel title, upload-playlist identifier, and public statistics such as views, likes, comment counts, subscriber counts, and channel totals when available. It also receives search context such as query, language, region filter, and publication-time filter. A region filter describes API search availability/filtering; it does not identify a creator’s or viewer’s location.

Information stored locally

The local SQLite database may contain the API fields listed above, timestamped statistics snapshots, collection and discovery state, channel/video associations, search attribution, and locally calculated classifications or scores. The application also stores polling progress for the Telegram bot. The bot receives Telegram update and chat identifiers to enforce its configured allowlist and handle commands. Message text is processed to route commands; the current design does not intentionally store a user message archive. Telegram itself processes messages under its own terms and privacy practices.

Credentials (the YouTube API key and Telegram bot token) are configuration secrets. They must not be published or included in this website, reports, screenshots, or audit attachments. No Google OAuth flow is implemented in the current project.

Purposes

Data are used to discover and organize public toy-related videos, review relevant metadata, operate the owner-restricted Telegram interface, and prepare internal market-research leads. The tool does not establish product sales, current market demand, buyer geography, or profitability from YouTube engagement counts.

Retention, refresh, and deletion

YouTube API Data must be refreshed or deleted in accordance with the applicable YouTube API Services Developer Policies. The local cleanup routine removes raw API records at 30 days, including saved snapshots, video/channel metadata, discovery records, and collection queues. While derived analytics are disabled, the routine clears derived tables and known generated Markdown/PDF outputs and the application’s named report cache. Raw Discovery experiment exports carry a refresh/delete-by date in their manifest and are removed by the cleanup routine after that date. The retention cleaner also rewrites recognized project SQLite backup copies using a temporary database and atomic replacement. These actions occur only when the cleanup operation is run; no schedule was installed as part of this project work. The owner must verify any backup or copy stored outside the recognized project paths before making a complete-compliance claim.

A local operator workflow records deletion requests for a video or channel, requires manual review and explicit confirmation, removes corresponding local records and generated reports, and updates recognized SQLite backups. It is not a public request form and does not delete content from YouTube. The owner must provide a monitored contact at leonidzadoroznyj@gmail.com and manually enter requests through that workflow. Google/YouTube and Telegram may separately retain data under their own policies.

Access, sharing, and security

Access to bot commands is restricted by a configured Telegram chat allowlist. Local database and configuration access is controlled by the host’s operating-system permissions. No absolute security guarantee is made. The project does not sell personal information. Data are shared with Google/YouTube as required to call the API and with Telegram when the bot receives or sends messages; third-party services apply their own terms and privacy policies.

Derived analytics

The project retains local product-classification and scoring algorithms for possible future use. A configuration gate defaults to off and requires an owner-recorded approval status and reference before the calculation/report paths are enabled. This is an application safeguard, not Google approval verification. Previously stored outputs are not shown by the bot while the gate is off and are cleared by the cleanup operation. Any permitted derived metric must be clearly and prominently identified as independently generated and must not be presented as a metric provided or endorsed by YouTube.
