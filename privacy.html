Information obtained from YouTube

When an owner runs collection, the application uses YouTube Data API Services with a locally configured API key and no Google OAuth user authorization flow. Depending on the API method and response, it may receive public video/channel IDs, titles, descriptions, tags, publication timestamps, duration, thumbnail URL, channel title and upload-playlist ID, plus public statistics such as views, likes, comments, subscriber counts and channel totals when available. Discovery also stores search query, language, region filter, publication window/order and discovery time. A region filter describes the API search request; it does not establish creator, viewer or buyer location.

Information stored locally

The SQLite database stores video and channel metadata, timestamped public-statistic snapshots, discovery/collection state and search attribution. It also stores quota reservations and Telegram polling progress. Telegram updates provide chat and update identifiers used to enforce access and avoid reprocessing. Command text is processed to route bot requests; the inspected handler does not intentionally maintain a message archive. A manually curated product-evidence registry can contain source video IDs and product/source notes. Generated Markdown and PDF reports may repeat selected public API fields and links.

The YouTube API key and Telegram bot token are local configuration secrets. They must not be published or included in screenshots, reports or audit attachments. The project does not implement Google OAuth.

Purposes

Information is used to discover and organize public toy-related video sources, retrieve public statistics, operate an owner-restricted Telegram interface, and prepare internal research leads. YouTube engagement does not establish product sales, current market demand, buyer geography or profitability.

Refresh, retention and deletion

The daily systemd timer runs the local cleanup once per day. It removes YouTube API data older than 30 days using their API refresh/discovery timestamps, including video/channel metadata, statistic snapshots, discovery associations and collection queue entries. It expires matching video references in the manual product registry; invalidates generated Markdown, PDF and HTML catalog files when source data expire; clears the application’s recognized report cache; and rewrites recognized SQLite backup files through a temporary copy with integrity checks. Known report copies in the project’s backups/ folder expire after 30 days; source-code backups are retained. Raw Discovery experiment folders are removed when their manifest’s delete-or-refresh date passes. With the derived-analytics gate off, derived database tables and trend outputs are cleared; if that gate is approved and enabled, derived rows have a 36-month limit.

The cleanup covers the working project and recognized files under its database/, reports/, config/ and backups/ paths. It does not discover or delete copies outside those paths, including off-device or manually copied backups, files already downloaded/shared by users, any copies held by third-party services, or host system journal records.

A local operator CLI records a deletion request for a video or channel and requires explicit confirmation before changing local records and recognized database backups. It invalidates generated reports but does not delete data from YouTube or Telegram. Privacy requests can be sent to leonidzadoroznyj@gmail.com.

Access and sharing

Telegram commands are restricted by the configured chat allowlist. Local database and configuration access relies on Raspberry Pi file permissions. Data are sent to Google/YouTube when the owner calls its API and to Telegram when the bot receives or sends messages. Those services apply their own terms and privacy practices. The project does not sell personal information. No absolute security guarantee is made.

Analytics and images

The project keeps proposed product-identity, independent-author, new-author-arrival and view-dynamics algorithms in source. The fail-closed configuration gate is currently disabled; real YouTube classification, cross-video/cross-channel aggregation, scoring and distribution are not enabled. Synthetic fixtures are used for formula tests. Unique channel IDs are not treated as verified independent owners. The current report embeds no real YouTube thumbnail or product photograph. A local image is accepted only when it is tied to the exact item and has a documented permission or license; none is currently approved in the image registry.
